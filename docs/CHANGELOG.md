## 2026-10-23 — build: calls hear you 60 ms sooner (group G4, behind a switch that is off)
- The call library holds your voice back before it plays it to Kairo: for audio it keeps up to 16 packets and waits until 4 later ones have arrived, so every turn reaches the PC 80 ms late (82.5 ms measured from the phone's microphone to the decoded sound). One lost packet makes it worse for the rest of the call: the buffer waits for the gap until it is full, and from then on the whole call runs 280 ms late. With room for 8 packets and waiting for 1, it is 20 ms (22 ms measured), and after a lost packet 120 ms.
- New switch `g4.jitter_patch`, **off by default** (it changes the call library's own inner parts, so it waits for your OK). On, a call uses the small buffer. Read once at the start of each call: turning it on or off applies to the next call, never in the middle of one. The default for everything else is untouched.
- Safe by design: it only swaps one object in memory, for that call (nothing is changed for good, the next call starts from the library's own numbers again). It checks the library's version (1.15.0, the one Kairo pins) and the exact shape of what it replaces; on any other version, or anything it doesn't recognise, it touches nothing, writes the reason to the log (`left as it is: ...`) and the call runs as before. A test fails when the pin in requirements-voice.txt moves, until the patch has been checked on the new version. The tests that use the real library (and the delay measurement) are in tests/test_voice_rtc.py, which CI's two voice jobs, on Linux and on Windows, already run (the call packages are installed only there; the plain server job skips them). A test fails when a test file that needs those packages is not in both jobs. This change does not touch `.github/`, so it needs no hand-merge. It opens no connection and adds no outbound destination: `outbound.MODULES` is unchanged.
- Measured on a real RTP path between a fake phone and the call code (a test in tests/test_voice_rtc.py; sandbox CPU on a busy shared machine, **not the PC**): stock 81.8 ms clean and 281.4 ms after one lost packet; patched 21.8 ms and 121.7 ms. So 60 ms less on every turn and 160 ms less for the rest of a call after a loss. The packet counts behind it are exact (4 → 14 against 1 → 6 packets of 20 ms) and are a test too. A buffer of 4 packets lost 6.5 % of the audio under 60 ms of network jitter in the plan's sweep, so 8 is the smallest that is safe.
- What it does not do: a lost packet still leaves the call 120 ms late for the rest of that call (it is smaller, not gone). How often a call loses a packet on your line is not known yet: on the PC, `tailscale ping` and the phone's jitter log (P11 in the voice plan) will say.
- Found while building it: the plan put the call in `build_call`, but by then the library has already built the call's audio receiver (it does so while it takes the phone's offer), so a patch placed there would only reach the call after. It runs in `voicertc.connect()` instead, right after the offer was taken and before the first packet.
- To do by hand: nothing happens until you switch it on. Open More → System → Experiments and turn on `g4.jitter_patch` (if your version doesn't show that page yet, ask Claude to switch it on). Then place a call; Kairo's log (`C:\Kairo\data\logs\kairo.log`) shows `rtcjitter: audio jitter buffer 16/4 -> 8/1 (aiortc 1.15.0)` for that call, or `left as it is` with the reason. To see whether it helps on your line, run Voice speed before and after (the 60 ms come off the network part of a turn, which is what is left after the PC's own steps). If a call sounds choppy with it on, turn it off again: that is the only thing it can change.
- Removed: nothing. It replaces nothing that exists (the library's own buffer is still what every call gets unless you turn the switch on).

## 2026-10-23 — build: speech to text on calls, the Whisper part of the voice plan (group G2)
- Calls write your words down with fewer surprises. Four fixes are on from the next update, each with a switch in More → System → Experiments (the names start with `g2.`): `g2.temperature_zero` (on): a sentence is decoded once, never again with random variation when Whisper is unsure (its default list goes up to 1.0 and can run the decode up to six times, with different words each time).
